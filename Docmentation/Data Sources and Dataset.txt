4. Data Sources and Dataset Preparation
The Rule Intelligence Engine (RIE) is designed as a standalone, domain-independent system and therefore does not rely on any existing production application, customer database, or client-specific business data. During development and evaluation, the system will be trained and tested using controlled datasets generated from synthetic business environments, publicly available datasets, and manually reviewed examples.
The primary objective of this approach is to create reproducible, domain-independent datasets for both feedback classification and structured rule extraction while ensuring that no sensitive production data is required during development. Separate datasets are maintained for classification, rule extraction, duplicate detection, conflict detection, and evaluation to enable independent training and assessment of each machine learning component.
4.1 Synthetic Feedback Dataset
The synthetic training data consists of independently annotated datasets for feedback classification and structured rule extraction. The initial dataset contains approximately 500–1,000 labelled business feedback examples covering all supported feedback categories, rule types, and business domains.
The datasets are generated using a combination of manually written examples, programmatic generation techniques, and Large Language Model (LLM)-assisted data generation. Every generated example is manually reviewed and annotated before being included in the training datasets to ensure label quality, annotation consistency, and reproducibility.
The synthetic dataset includes diverse feedback patterns such as:
Metric definition changes 
Filter rules 
Status mappings 
Join corrections 
Time-based rules 
Entity definitions 
Calculation corrections 
Data-quality issues 
Access and scope rules 
Duplicate and near-duplicate feedback 
Contradictory rules 
Ambiguous feedback 
Non-rule product feedback 
Feedback containing grammatical errors 
Hinglish and conversational English examples 
Feedback containing multiple business rules in a single message 
Missing or incomplete business context 
The datasets include examples containing single-rule and multiple-rule feedback, conversational English, Hinglish, incomplete business requirements, and ambiguous business intent. Each example is annotated separately for classification labels and structured rule extraction using predefined annotation guidelines to support independent evaluation of each machine learning task.
These variations improve the ability of both the deterministic baseline and machine learning models to generalize across different writing styles, business domains, conversational language, Hinglish, and multiple-rule business feedback.

4.3 Public Datasets
Public datasets are incorporated to make the synthetic business environments more representative of real-world data distributions.
Suitable public sources include:
Kaggle datasets 
UCI Machine Learning Repository 
Government open-data portals 
Public customer-support datasets 
Public e-commerce datasets 
Open-source sample databases such as Northwind and Chinook 
Public datasets are used primarily to provide realistic schemas, attribute names, business terminology, and domain context. Since these datasets do not contain labelled business feedback or structured rule annotations, corresponding feedback examples are generated and manually annotated before being included in the project. Separate annotations are maintained for feedback classification and structured rule extraction to support independent model training and evaluation.
Public datasets are used only for development and evaluation purposes. All generated annotations undergo manual review before inclusion in the project datasets to ensure label consistency, reproducibility, and compatibility with the predefined annotation guidelines.
4.4 Manually Reviewed Evaluation Dataset
To ensure unbiased and reproducible evaluation, the project maintains a separate manually reviewed frozen evaluation dataset that is never used during model training, validation, or hyperparameter tuning. This dataset serves as the reference benchmark for comparing the deterministic baseline with candidate machine learning models.
This evaluation dataset contains:
Business feedback
Expected classification labels
Expected structured business rules
Duplicate relationships
Conflict relationships
Clarification requirements
Expected reviewer decisions
Ground-truth structured rule representations
The dataset serves as the ground truth for measuring classification performance, structured rule extraction accuracy, duplicate detection, conflict detection, clarification handling, and overall system behavior. All candidate machine learning models are evaluated against this frozen evaluation dataset and are promoted only if they demonstrate measurable improvement over the deterministic baseline according to the predefined acceptance criteria.
4.5 Data Preparation Strategy
The overall dataset is divided into independent subsets for model development, validation, and evaluation. Separate datasets are maintained for feedback classification, structured rule extraction, duplicate detection, conflict detection, and clarification handling to enable independent training and assessment of each machine learning component.
Dataset	Approximate Size	Purpose
Training	~600 examples	Model training
Validation	~150 examples	Hyperparameter tuning and threshold selection
Frozen Evaluation (Testing)	~200 examples	Final performance evaluation and baseline vs candidate model comparison
Duplicate Pairs	~150 pairs	Duplicate detection evaluation
Conflict Pairs	~150 pairs	Conflict detection evaluation
Ambiguous Examples	~100 examples	Clarification handling evaluation
To prevent data leakage, paraphrases of the same underlying business rule are always kept within the same dataset split. The frozen evaluation dataset remains unchanged throughout model development and is used exclusively for final benchmarking and comparison between the deterministic baseline and candidate machine learning models.

4.6 Data Privacy and Independence
The Rule Intelligence Engine is intentionally designed to operate without any dependency on production environments or customer-specific business data.
During development:
No production customer data is used. 
No existing product database is required. 
No client-specific business rules are referenced. 
All datasets are anonymized, synthetic, or publicly available. 
Production feedback, if incorporated in future versions, must first undergo manual review and anonymization before being considered for training purposes. 
This approach ensures that the system remains portable, reproducible, privacy-compliant, and suitable for deployment across multiple business domains. Any future incorporation of production feedback must follow defined data governance policies, including anonymization, manual review, dataset versioning, and approval before inclusion in any training or evaluation dataset.
4.7 Dataset Annotation Guidelines
To ensure consistency across training and evaluation datasets, every feedback sample follows a standardized annotation process. Separate annotations are maintained for feedback classification and structured rule extraction to support independent model training and evaluation.
Each feedback instance is annotated with the following attributes:
• Feedback Type
• Rule Category
• Actionability
• Clarification Requirement
• Business Term
• Operation
• Conditions (Field, Operator, Value)
• Scope
• Time Window
• Threshold Values
• Affected Tables and Columns
• Duplicate Relationship
• Conflict Relationship
• Number of Extracted Rules
• Named Entity Recognition (NER) Labels
Named Entity Recognition annotations identify business entities such as Business Terms, Operations, Tables, Columns, Conditions, Threshold Values, Scope, and Time Windows. Feedback containing multiple independent business rules is annotated with separate structured rule representations for each extracted rule. Hinglish and conversational English examples follow the same annotation guidelines to ensure consistent labeling across different writing styles.
All annotations are independently reviewed by at least two reviewers. In cases of disagreement, the sample is escalated for senior review before being included in the gold-standard evaluation dataset.
These annotation guidelines ensure consistent labels across all datasets, improve annotation quality, and support reproducible evaluation of both the deterministic baseline and candidate machine learning models.
4.8 Dataset Distribution and Rule Families
To reduce class imbalance and improve model generalization, the synthetic dataset maintains balanced representation across all supported business rule categories while preserving relationships between logically equivalent business rules.
The approximate dataset distribution is shown below.
Category                     Approximate Distribution

Metric Definition                    30%
Filter Rules                         20%
Mapping Rules                        15%
Access Rules                         15%
Data Quality Rules                   10%
Ambiguous / Clarification Cases      10%
Logically equivalent business rules are grouped using a unique rule_family_id. The rule_family_id identifies paraphrases or equivalent representations of the same underlying business rule. It is not used to group different rules extracted from the same feedback submission. Feedback and extracted rules remain linked through feedback_id and suggestion_id.
For example:
Rule Family ID: RF001
• Revenue should exclude cancelled orders.
• Cancelled orders must not contribute to revenue.
• Revenue calculation should ignore cancelled orders.
Although these feedback statements differ linguistically, they represent the same underlying business rule and therefore share a common rule_family_id.
This grouping enables robust duplicate detection evaluation while preventing logically equivalent rules from being distributed across different dataset splits. Different business rules extracted from the same feedback receive separate extracted rule records while sharing the same feedback_id, but they are assigned different rule_family_id values unless they represent equivalent business logic.
4.9 Dataset Versioning and Source Tracking
Every dataset used by the Rule Intelligence Engine is version controlled to ensure reproducibility, traceability, and consistency across model training, evaluation, and deployment. Each model evaluation and analysis run references the corresponding dataset version used during execution.
Each dataset version records:
• Dataset Version
• Creation Date
• Source
• License Information
• Annotation Version
• Number of Samples
• Business Domain
• Supported Machine Learning Task


The primary dataset sources include:
• Synthetic Feedback (Internal)
• Public Datasets (Original License)
• Business Glossary (Internal)
• Manual Annotations (Internal)
Maintaining dataset version history enables reproducible experiments, simplifies comparison between different model versions, and ensures that every evaluation run and analysis run can be traced back to the exact dataset version used during execution.
